## 4. AI 接手后的维护工作（重点）

### 4.1 已提交：`adae5aa`（2026-08-15）— 后台角色回合开始/结束选牌卡死修复

背景：`HookPlayerChoiceContext` 用 `LocalContext.NetId` 作为 `_localPlayerId` 构建选择上下文，当"最近可见角色 ≠ 正在触发选择的角色"时，`HookPlayerChoiceContext.cs:194/206` 处 `_gameAction.OwnerId != _localPlayerId`，选择动作永远不会被本地入队 → 保留手牌等效果卡住或被跳过。

提交内容（4 个文件，+241/-99）：
- 新增 `HookPlayerChoiceContextLocalPatch.cs`：构造器后强制 `_localPlayerId` 归属到选择角色。
- 新增 `CombatManagerTurnHookForegroundPatch.cs`：在 `SetupPlayerTurn` / `DoTurnEnd` / `FlushPlayerHand` 前把前台自动切到对应角色。
- 重写 `CardSelectForegroundSwitchPatch.cs`：`CallDeferred` 延迟切前台 → 同步切前台，覆盖 `FromHand` / `FromHandForUpgrade` / `FromSimpleGrid` / `FromChooseACardScreen` / `FromCombatPile`。
- `LocalMultiControlRuntime.cs`：新增 `TryEnsureForegroundForPlayer`，同步切前台并在失败时回滚。

**严重问题（本次分析实证发现）**：这个提交里所有补丁类**只有方法级 `[HarmonyPatch]`、没有类级标记**。我用游戏自带的 `0Harmony.dll`（版本 2.4.2.0）做了最小复现实验：`PatchAll` **只应用带类级 `[HarmonyPatch]` 的类，方法级-only 的类被静默跳过**（实测 `GetPatchedMethods()` 只返回带类级属性的那一个）。也就是说 `adae5aa` 的修复**在运行时根本没有生效**，直到工作区里补上类级标记才真正启用。

### 4.2 未提交工作区（v1.32 进行中，约 2026-08-19/20）

相对 `merge-110-test`，工作区净改动 +596/-165，涉及 15 个文件 + 3 个新文件：

**A. 修复"类级 `[HarmonyPatch]` 缺失"（关键）**
- `CardSelectForegroundSwitchPatch.cs`：补类级 `[HarmonyPatch]`（配合方法级目标），并把 `CurrentChoicePlayerId` 改为 `AsyncLocal` 沿异步链传递，新增 `FromHandForDiscard` 入口。
- 新增 `NPlayerHandSelectCardsSerializationPatch.cs`（类级 `[HarmonyPatch]`）：战斗内手牌选牌**串行化**。
  - 问题：两个本地角色在同一个同步点先后调用 `NPlayerHand.SelectCards`（如双方同时持有灵乌路空「炉心融解」时回合开始各自选牌），共享的 `_selectionCompletionSource` 被第二次调用覆盖 → 第一个选择永久悬挂（软锁：无法出牌/结束回合）。
  - 方案：`SemaphoreSlim` 全局闸门同一时刻只允许一个选牌进行中；用 `AsyncLocal<bool>`（而非静态标志）标记"包装内重入原始实现"，使 ActionExecutor 的兄弟调用链被正确拦下串行等待；展示前按选择归属者把前台切到正确角色。
- `HookPlayerChoiceContextLocalPatch.cs`：补类级标记，日志降噪（同键只打一次），`Warn`→`Info`。

**B. 新增 `HookEnqueueForegroundPatch.cs`（新文件，未跟踪）**
- 在 `ActionQueueSynchronizer.EnqueueHookAction` **入队瞬间**（此时已可确定 `GenericHookGameAction.OwnerId`）同步切前台到所属玩家，早于选牌 UI 弹出，避免回合循环执行顺序导致弹窗展示错误角色的手牌。

**C. v0.111.0 适配（lanternX 提交的延续 + 本轮补齐）**
- `LocalLoopbackHostGameService`：`INetHostGameService` 新增成员——实现 `LocalVersion`、`GetVersionInfoForPeer`（返回 null），补 `ClientConnectionFailed` 事件。
- `LoadRunLobbyPatch`：`LoadRunLobbyPlayer.versionInfo` 字段被拍平为 `isModded` bool，改用 `NetService.LocalVersion.IsModded()`。
- `NCustomRunLocalSelfCoopPatch` / `LocalSelfCoopContext`：`StartRunLobby.MaxPlayers` 被替换为构造注入的 readonly `_maxPlayers`，删除基于反射的 `EnsureLobbyMaxCapacity` 扩容；大厅以 `MaxLocalPlayerCount`（12）满容量创建。
- `CombatManagerReadyEnemyTurnPatch`：`_playersReadyToBeginEnemyTurn` 集合从 CombatManager 移到了 turn state，改为先取新路径属性、再回退旧字段；同时**删掉了原来的"敌方回合未推进兜底"Postfix**（可能是新版不再需要，或是回归隐患，需关注）。
- `Entry.cs`：新增 Harmony 打补丁方法统计日志（`GetPatchedMethods()` + 对 SelectCards/FromHand 等关键方法的清单打印），用于快速确认补丁真的挂上了——正是这一诊断能力暴露了 4.1 的"静默跳过"问题。

**D. 回合结束按钮修复（`LocalMultiControlRuntime.cs`）**
- `ReevaluateEndTurnButtonState` 重写：以 `LocalContext.GetMe(combatState)` 判断 `canTakeAction`（存活且未 ready），修复切人后回合结束按钮消失/状态陈旧。
- 新增 `TryRepairEndTurnButtonOffscreenPosition`：检测按钮 `AnimOut` 残留（离屏但已启用）时强制重放 `AnimIn`。
- 新增"延后补刷战斗 UI"：切人时若正处于出牌/选牌流程（`IsCombatUiInPickFlow`），不再回滚上下文，而是等流程结束后补刷（最多 40 帧重试），避免"逻辑 owner 与显示 owner"分离。
- 新增 `TryGetCombatPlayer` / `TryEnsureForegroundForPlayerId`：给只有 NetId 的挂点（hook 入队等）解析 Player 并切前台。

**E. 元数据与文档**
- 版本号 `1.31.0` → `1.32.0`（`DualRoleAdventure.json`、`mod_manifest.json`）。
- `CHANGELOG.md`：新增 `[Unreleased]`（选牌串行化/类级补丁修复）与 `[v1.32]`（v0.111.0 适配）两节。
- `AGENTS.md`：语言规则从 English 改回 **Chinese**（与原规则一致）。

**F. 诊断探针（新增，未跟踪）`NEndTurnButtonLifecyclePatch.cs`**
- 记录 `SetState` / `OnTurnStarted` / `OnAboutToSwitchToEnemyTurn` / `AfterAllPlayersReadyToBeginEnemyTurn` / `NCombatUi.Activate` 时按钮状态与位置，用于定位"第一回合结束时按钮失踪"的时序。
- **注意**：该文件同样只有方法级 `[HarmonyPatch]`，**探针当前不会触发**（PatchAll 跳过）；且带 UTF-8 BOM、缺末尾换行。应补类级标记或作为临时诊断代码在发布前移除。

### 4.3 一个需要你确认的取舍

`CombatManagerReadyEnemyTurnPatch` 里删除了"敌方回合未推进时本地兜底推进"的 Postfix（原实现用反射调 `AfterAllPlayersReadyToBeginEnemyTurn` 强制推进）。如果 v0.111.0 下"所有玩家已 ready 但敌方回合卡住"的场景仍需兜底，这个删除可能引入回归——建议对照 `src/`（反编译参考）确认新版本 CombatManager 是否已自带该推进逻辑，再决定是否保留等价兜底。

## 5. 代码库结构与规模

- 源码：`Scripts/` 下共 **98 个 .cs 文件**：`Patch/` 77 个（按场景分：大厅、战斗、地图、奖励、休息区、商店、事件、特定遗物）、`Runtime/` 17 个、`Models/` 1 个、`Rewards/` 2 个、`Entry.cs` 1 个。
- 核心对象：
  - `LocalLoopbackHostGameService` — 无真实网络、可变更 NetId 的 `INetHostGameService` 回环实现。
  - `LocalSelfCoopContext` — 主开关：启用状态、目标人数（2~12）、本地玩家 ID、Vakuu 分配。
  - `LocalMultiSessionState` / `LocalMultiControlRuntime`（约 69 KB，最大文件）— 会话排序与落地一次"切人"（net service sender + `LocalContext.NetId` + 各同步器本地玩家重同步 + UI 刷新）。
  - `LocalGhostHandsRuntime` — F8 幽灵手牌叠层（NodePool 借用/归还）。
- 无自动化测试（AGENTS.md 明确：维护者手动试玩 + 读 `%APPDATA%\SlayTheSpire2\logs\godot.log`）。
- **`src/` 反编译参考树当前不存在**（gitignored，需按 AGENTS.md §5 用 ilspycmd 重新生成）。v0.111.0 的 API 变动是通过编译期错误 + 字符串反射目标人工核对完成的。
